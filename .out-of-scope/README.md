# 范围外决策账本（.out-of-scope/）

> 记录**明确决定不做**的事：决策、理由、拒绝出处、现有 workaround、复查触发条件。
> 与 `docs/adr/` 互补：ADR 记"做的决策"，这里记"不做的决策"。review 产出的范围外观察（fix-review 的 O*）若确认为"不做"，也沉淀到这里。

## 优先级：本目录是历史决策账本，不是禁令

新的显式决策（issue、spec、用户当轮指令）**永远优先**于本目录任何条目。
条目挡的是"不知情的重复劳动"，不挡"知情的重新决策"。新任务撞上某条记录时：

```text
用户指令明确且知情（引用了旧 issue / 明说"现在要做"）
      → 直接执行；同 PR 删除该条目，并在 docs/adr/ 记录反转理由
用户可能不知道曾有拒绝记录
      → 提醒一次（"此事拒绝于 #N，理由 X，复查触发条件 Y"）→ 等确认
            ├─ 确认推翻 → 执行 + 删条目 + 补 ADR
            └─ 撤回     → 条目保留
```

## 条目模板

每个决策一个文件 `<slug>.md`（英文 kebab-case），字段齐全才算合格条目：

```markdown
# <决策标题>

**决策**：<一句话，不做的是什么>
**理由**：<为什么不做——技术约束 / 边界归属 / 成本>
**Rejected in**: #<issue 编号>
**现有 workaround**：<用户今天怎么绕过>
**复查触发条件**：<什么变化后应重评；当前无已知条件时如实写"无">
```

**复查触发条件必须填**：这是条目自带的可推翻性——一段时间后想重新决策时，
它给出判断依据，而不是让 agent 拿旧文件压新决策。触发条件已到，条目自己指路；
没到，也能看出卡在哪。
