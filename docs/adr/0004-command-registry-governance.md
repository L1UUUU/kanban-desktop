# ADR 0004 — 命令注册表治理：零内置冻结与三条判据

> 状态：已接受（用户 2026-11-13 确认砍到零内置）· 日期：2026-11-13
> 关联：spec #82 E 块（斜杠命令）、issue #92（派发闭环，验收随本 ADR 更新）；参考 PI-Desktop ADR 0106（第一方注册表从 15 个砍到 5 个）与 ADR 0024（命令三源合并、未知名降级为普通文本）
> 现状基线：#82 spec 原定义 `/pty`（当前项目开终端）与 `/kanban`（切看板）两个内置应用命令

## 背景

PI-Desktop 的第一方命令注册表曾膨胀到 15 个：其中大量是**已有专属 UI 的动作**（删除会话、打开设置、重载窗口）也注册成命令，注册表暗示了 App 并不真正一致的契约，命令发现变成噪声。ADR 0106 砍到 5 个，判据清晰且长期有效。kanban 的斜杠命令系统（#82）刚起步，起步时就应固化判据，避免重走膨胀弯路。

## 决策

**1. 第一方内置命令注册表冻结为零。** 原定的 `/pty`、`/kanban` 移除：两者均已各有专属 UI 入口（侧栏「＋」菜单开 PTY、顶栏视图切换看板），按判据 2 不进命令表。斜杠菜单的内容源仅为 CLI 命令源（claude skills / codex prompts / opencode 原生命令）；fake 会话（无命令源）下菜单为空态，空态文案引导而非填充占位命令。

**2. 三条治理判据**（未来任何"要不要加内置命令"的讨论以此为准）：

- **专属 UI 判据**：已有专属控件/入口的动作不进命令表（命令表是键盘流的补充，不是导航的复制品）。
- **降级判据**：未匹配的 `/foo` 一律作为普通文本原样发送（三 CLI 行为一致），不报错不拦截。
- **来源分离判据**：CLI 命令源与（未来的）插件命令源独立贡献命令，不占第一方名额；第一方要新增命令必须先过专属 UI 判据并更新本 ADR。

**3. issue #92 的派发闭环相应简化**：不再实现 `/pty` `/kanban` 的本地执行与重名优先级分组；菜单分组退化为单组（CLI 命令源）。

## 后果

- 斜杠菜单的契约最小且稳定：纯 CLI 命令发现与触发，第一方零维护面。
- 键盘流用户的 /pty、/kanban 快捷用法不提供——侧栏与顶栏入口 + 未来全局快捷键是替代路径。
- 未来出现"确无专属 UI 的高频动作"（如上下文压缩类）时，按判据 2 的来源分离原则评估新增，须修订本 ADR。
- #82 spec E 块的"内置命令"验收条款由本 ADR 取代（spec 正文不再作为该细节的权威）。
